# 2 · Components: clean or imaginary

Audit the real product UI before designing frames. The full rule is in [`components/`](../components).

```
Is the real UI clean, current and on-brand?
├─ yes → CAPTURE: npx hyperframes capture <url>  → tokens, fonts, logos, real copy
│        rebuild the 3–6 key components in HTML with those tokens and animate them
└─ no  → IMAGINE: design 3–6 imaginary components in the brand tokens
         each one shows ONE true capability, simplified
```

**Inventory (write it into the brief):**
- the one *proof* component: the moment the product does its job (an anomaly flag, a finished payout, a merged PR),
- two or three *supporting* components (a list, a chart, a toast, a command bar),
- the *brand* elements: official logo files only, the colour tokens and the fonts.

**Gate:** you sign off on the component list and on "real vs imaginary" for each item.
